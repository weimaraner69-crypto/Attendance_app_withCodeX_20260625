# 制約仕様

勤怠管理アプリの実装判断で必ず守る制約です。設計の背景は `docs/implementation-decisions.md`、DB の詳細は `docs/database-design.md` を参照します。

## データと権限

- 勤怠イベントは監査ログとして保持し、通常の修正で削除しない。
- PIN、API キー、Secret key は平文で保存・出力しない。
- service role key はサーバー専用とし、ブラウザへ公開しない。
- 権限は組織・店舗・ロールの境界を越えない。

## 打刻

- 店舗 iPad 打刻は PIN 検証後にのみ記録する。
- 個人スマホ打刻はログインと GPS 検証を必要とする。
- LINE は GPS 付き Web 打刻への導線として扱い、直接打刻の入口にしない。

## 外部連携と運用

- 日報アプリ連携は読み取り専用 API に限定し、勤怠アプリを正本にする。
- migration、認証、権限、秘密情報、外部連携 API の変更には検証手順とロールバック方針を残す。
- 実データや秘密情報を Issue、PR、ログ、生成物へ含めない。
